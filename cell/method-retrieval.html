M2 Retrieval

Construction Retrieval Integration Verification

Retrieval decides which stored knowledge the system can actually use, since a generator reasons only over what retrieval returns. In science the difficulty is that the query and its target are often not both text. Matching a question to a passage is routine, but matching a spectrum to a molecule or a symptom to a graph node is not, so the matching operation is fixed by the substrate rather than chosen freely. Formally, retrieval builds the set of the pipeline equation through a query transform, a query encoding, and a match score. Of these, only is substrate-bound, matching against the keys that the encoding shaped at construction. The rest of this section covers each substrate's matching operation, together with which store to query and whether to retrieve at all.

Query transformation

The text a user submits is often not the best text to search with, so many systems rewrite the query before encoding it, which is the role of the transform. The rewrite may add reasoning, broaden coverage, or break a hard question apart. RAG searches with a generated rationale instead of the bare question, so the retriever sees the reasoning the answer will need. Pathfinder expands the query into a hypothetical answer and searches with that, on the premise that a plausible answer looks like the passages that support it. SQuAI splits a complex question into sub-questions and retrieves for each, and HyKGE emits an intermediate hypothesis to widen its exploration of the graph. BioRAGent expands the query with synonyms and related terms generated from a few examples, so a document that uses different wording is still found. Because it acts on the query alone, this step is independent of the substrate and helps every objective.

Substrate-fixed matching

Matching is where the substrate asserts itself, because whether a stored item counts as similar to a query depends on what kind of thing that item is. A passage can be compared by its words or its meaning, but a molecule, a graph node, or an image cannot be compared the same way, so each Knowledge Source carries its own matching operation. Over the Textual substrate, matching is similarity between texts, measured either lexically by shared words or densely by shared meaning in an embedding space. MEDRAG runs several such retrievers together, BM25, Contriever, SPECTER, and MedCPT, and merges their rankings by reciprocal rank fusion. Over the Relational substrate the index is a graph, so matching means walking its edges outward from the query entities. KG-RAG takes the immediate neighbors of a node in SPOKE, MindMap follows longer multi-hop paths between two query entities, and GraPPI slides a nearest-neighbor window across the STRING protein graph. Over the Structured-entity substrate, items are matched by their structure rather than by any text describing them. f-RAG retrieves molecular fragments ranked by a target property, and RetMol retrieves whole exemplar molecules that best satisfy the target property. Keying on structure this way is what lets these systems serve Molecular Design. Over the Perceptual substrate the query is a raw signal compared directly to candidates. MMed-RAG sends a query image to a retriever trained for its imaging domain, and PathoAgenticRAG finds page-level pathology-textbook images by joint image-text similarity. When the knowledge instead lives behind a database rather than a local index, matching is not a similarity computation at all but a call to that service. LLaMP lets a reasoning agent query the Materials Project, and GeneGPT writes and runs NCBI web-service calls, each returning an exact value to ground the answer.

Source planning and adaptive retrieval

Before any of these matches runs, a system may have to make two prior decisions. The first is where to look, when the knowledge is split across several stores of different kinds. Omni-RAG handles this with a small trained planner that routes a medical question to the right member of a five-source knowledge base spanning text and a graph. The second decision, which matters more in science than in general search, is whether to retrieve at all, because pulling in an outdated protocol can be worse than retrieving nothing. Self-BioRAG therefore predicts on demand whether a given query needs retrieval, rather than retrieving for every one.

Scientific retrieval keys on representations that text similarity cannot address. A query given as a structure or a spectrum must be matched by an operation the substrate supports, so dense-vector retrieval alone reaches a passage but not a binding pocket.
